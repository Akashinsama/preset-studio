# 酒馆预设解析器 · 生成器

一个**零依赖、全本地**的酒馆（SillyTavern）预设工具包：双击一个 HTML 就能把任意预设拆开看、
体检、改结构、配面板外观、甚至从零搭一份；另配一个悬浮窗面板脚本（芳乃配色）。
不用 Node、不用服务器、不联网，**不改你的任何文件**——导出永远是"另存为"。

> ## ⚠️ 这个仓库里没有预设正文
>
> 这里发的是**工具与文档**，不是预设。开发期用来当样本的那些预设属于各自的作者，
> **不进这个仓库**（原因与署名见 [`NOTICE.md`](NOTICE.md)）。
> 所以依赖样例预设的测试会打印 `SKIP` 并正常退出——**没跑 ≠ 通过**；
> 想让它们真跑起来，按 [`samples/README.md`](samples/README.md) 放一份你自己的样例。

## 30 秒上手

1. 双击 `tools/gui/index.html`（打包版是根目录的 `开始.html`）。
2. 右上角 **导入预设…** 选一份你自己的酒馆预设 JSON（可多选）。
3. 左栏第一项 **引导：我要做什么**，会按"你手上有什么、想改到哪一步"给清单。

界面上**来源条目的正文只读**，逐字节哈希校验保证"没动过"。
右上角的 **⟳ 刷新** 只重挂当前这一屏用来解卡（不重载页面，输入与草稿都保留）。

## 自检怎么跑

**先跑一句**（造合成夹具 + 把整条链跑完，之后所有测试都能真跑）：

```bash
node tools/build-all.mjs          # make-fixture → build-regex → build-panel → build-preset
                                  # → build-preview → build-gui-demo → build-package
```

```bash
node tools/selftest.mjs           # 72 项   包内自检：库 + 面板 + 样例预设
node tools/test-regex.mjs         # 30 项   思维链折叠链逻辑
node tools/test-gui.mjs           # 353 项  解析 / 拼装内核 + M3 编辑端到端
node tools/test-panel.mjs         # 155 项  面板逻辑（假 DOM）
node tools/test-panelconfig.mjs   # 101 项   面板外观配置夹取一致性
node tools/test-mobile.mjs        # 20 项   手机场景
node tools/test-iframe.mjs        # 34 项   iframe 与时序
node tools/check-preset.mjs       # 108 项  样例预设的独立校验
node tools/check-browser.mjs      # 58 项   面板布局（真浏览器，本机 Chrome/Edge）
node tools/check-gui-browser.mjs  # 十屏    生成器 GUI 的 DOM 取证（真浏览器）
```

实测：**790 项全绿**（上面除浏览器两层）+ 浏览器两层在合成夹具上同样通过。

> **这些不需要你先准备任何预设。** 缺夹具时 `tools/lib/fixtures.mjs` 会自动调
> `tools/make-fixture.mjs` 造一份**合成夹具**：结构（条目名 / 槽位 / 顺序 / 开关）从 `spec/` 里
> 已经进库的规格推出来，正文全是「【合成夹具】…」占位，**不含任何预设正文**。
> 少数几条"真实规模"断言（226 条 / 60 条开启 / 30 条正则）在合成夹具下会**按夹具重算基准**
> 并打印一行说明——不是被放过，是换了基准。想看真实数字，把你的预设放成同名再跑一遍
> （见 [`samples/README.md`](samples/README.md)）。
>
> 真的连合成夹具都造不出来时才会打印 `SKIP` 并退出 0；`DSH_REQUIRE_FIXTURES=1` 把缺失变成失败。

## 附：配套预设「芳乃预设」的说明

> 下面这份文档描述作者自用的那份成品预设。**成品文件与预设正文不在本仓库**——
> 留着它是为了说明"这套工具是为什么做出来的"，以及面板脚本的设计约定。

一份自用酒馆预设（SillyTavern completion preset），配一个芳乃配色的悬浮窗开关面板。

## 结论先说

| 项 | 内容 |
|---|---|
| 成品 | `preset/芳乃预设.json`（固定文件名，构建时自动删掉旧的日期版，别导错） |
| 结构 | 照 `Kemini_Dramatron_v3.1.json`（顶层 47 字段、采样参数、槽位结构、插件配置） |
| 破甲 | 按模型分流：Gemini→Kemini / DeepSeek·GLM→梦鲸 / 其他→Izumi，面板上一键切换 |
| 功能 | Izumi 的条目全量搬入，收敛成 23 个子集（单选下拉框 / 多选开关排 / 可填输入框） |
| 面板 | `panel/fano-panel.js`，酒馆助手脚本，芳乃配色，自带悬浮球；外观与分组可配置，顶部按钮=隐藏/显示（v0.6.0） |
| 芳乃 | 只由新增的三条主体层条目实现（默认关） |
| 来源提示词 | **一字未改**，逐条哈希校验 |

## 装法

1. 装好并启用 **酒馆助手（JS-Slash-Runner）** 扩展。
2. 酒馆 → 预设（Completion Presets）→ 导入 → 选 `preset/芳乃预设.json`。
3. 左下角出现「芳」圆球，点开就是面板。面板脚本已内嵌在预设里，不用单独装。

> 如果同时装过 **消息压缩（Chat Squash）**、**Kemini 面板**、**NoAss** 这类依赖预填充的插件，建议关掉——它们会和预设抢预填充。预设里带的 `SPreset` 就是 Kemini 推荐的关状态。

## 面板怎么用

- **芳乃主体层**：三条，默认关。打开第一条就是让芳乃站在故事之上跟你说话。
- **破甲（按模型分流）**：先选模型定骨架，再调这套骨架的档位。档位不会被切换清掉。
- **思维链 / 思考方式（选一）**：Kemini 的 ICOT/COT 与 Izumi 的思维链都在这里，**只能选一个**。
- **MVU 变量更新（选一）**：一键开关。`不使用` / `MVU（普通）` / `MVU Zod（JSONPatch）`，选一项就完事，不再依赖别的模块。
- **自定义内容（自己填）**：7 条要你敲内容的条目，都是真正的输入框。
- **锚点（固定开启）**：12 条只读，不给开关——它们占住世界书/角色卡/主提示的注入位，切换模型也不会动。
- 其余模块默认折起，点标题展开；折起时标题右边仍写着当前状态。
- **🛡 防截断（顶部按钮）**：默认开。开了以后模型把正文放进一个合成函数调用的参数里回传，绕开「纯文本流被渠道掐断」那条路。开关存在浏览器里（键 `fano-antitrunc-v1`，**与 v2.8.1 那支共用**，换过来状态不丢）；关掉就把 `window.fetch` 上的包装整个摘掉。这一层是从 v2.8.1 搬来的，**逐项对照**（搬了哪些、改了哪几处、哪些没搬、哪些没验过）见 [`spec/防截断移植对照.md`](spec/防截断移植对照.md)。
- **长按条目改正文**：按住面板上任一条目（多选开关行、单选下拉下面那行"当前条目"、只读区里的名字）就打开它的正文编辑器，改完点保存——和其它操作一样**只写回预设一次**。手机上滑动就是滚动，不会误触；长按后紧跟的那次点击会被吞掉，所以不会顺手把条目开关掉。酒馆的**注入位标记**（聊天记录/角色卡/世界书这些位置标记）长按只给看：它们的正文必须为空，写进去会让对应内容进不了上下文。时长与开关在生成器的「面板外观 → 交互」里调。
- 改完任何选项不会跳回顶部；每次操作只写回一次预设。

### 思考方式与显示形态

**思考方式决定会吐几个思考块，思考块的个数决定显示成什么样子**：

| 你选的思考方式 | 模型吐出的块数 | 显示形态 |
|---|---|---|
| `📽️ICOT（三段）` | 3 块（它明确要求分三段） | **Kemini 形态**：每块一个朴素折叠条 |
| `📽️COT（格式友好型）` | 1 块 | **Izumi 形态**：毛玻璃卡片 |
| Izumi 系任一思维链 | 1 块（`konatan_planning~`） | **Izumi 形态** |

折叠条上的文字统一是「芳乃祈福中」。这套规则是**纯正则**实现的（4 条按顺序套用），不是脚本。

**为什么以前会混着出两种形态**：Kemini 的 ICOT/COT 走 `<thinking>`、Izumi 的思维链走 `konatan_planning~`，而源预设里这两套各自都是开的。两条互相矛盾的指令同时生效，模型就把两种都吐出来。现在面板按**标签**做了互斥：开了 Kemini 那套，Izumi 那套自动全关，反之亦然。组内不互斥（Izumi 的思维链本来就要和预填充尾部配对用）。

### 为什么锚点不能关

这 12 条是酒馆**注入世界书、角色卡、用户人设、聊天记录**的位置标记。早先的版本把它们误放进了 Gemini 破甲骨架里，结果**切到别的模型时上下文整体丢失**（世界书不注入、角色卡不见）。现在它们独立成 `anchors` 模块、组装时强制开启，并且有三道回归断言守着：构建期强制、成品校验期检查、面板测试期对四个骨架选项逐一验证。

## 打包（给别人的那份）

```bash
node tools/build-package.mjs     # → dist/芳乃预设生成器/ 与 dist/芳乃预设生成器.zip
```

包里是**整个编辑器 + 可编程的库 + 成品与源码 + 说明书**，示例素材**只有芳乃预设这一份**
（Izumi 是开发环境跑测试用的第三方预设，不进包——`build-package.mjs` 会强制检查这件事，
还会检查"index.html 引的每个文件都在包里"，因为 `file://` 下少一个文件就是白屏）。

包内可跑的自检（不需要第三方源预设，也不需要 Chrome）：

```bash
node tools/selftest.mjs                                  # 70 项
node tools/check-preset.mjs                              # 108 项
node tools/test-panel.mjs                                # 155 项
node tools/test-panelconfig.mjs                          # 101 项
node tools/test-mobile.mjs                               # 20 项
node tools/test-iframe.mjs                               # 34 项
node tools/test-regex.mjs                                # 30 项
```

不带进包的是：需要第三方源预设的 `build-{groups,regex,preset,preview}.mjs`（跑之前得先有夹具，
见下），以及一批本机专用的一次性诊断脚本 `diag-*`——后者已经删掉了：
它们写死读那三份预设，在克隆下来的仓库里**一跑就报错**，而"宁可不发，也不发一个跑起来就报错的脚本"
是这个仓库自己的规矩。需要时从 git 历史里取回来即可。

> 注意：本机文件沙箱下 `fs.rmSync` 是**静默失效**的（文件还在，甚至把进程搞崩），
> 所以 `build-package.mjs` 自己用 `unlinkSync` + `rmdirSync` 清目录。清目录这种事别偷懒。

**给 AI 的接口**：`tools/gui/API.md` 是那 8 个库的完整函数清单；
`说明书.md` 第二部分是"够用的最小知识 + 八段可直接跑的配方"。

**手机上打不开面板时**：面板启动会**自检并用酒馆自带的弹窗播报原因**（手机上一眼可见）；
也可以跑 `window.__FANO_PANEL__.diagnose()` 看详情，或 `window.__FANO_PANEL__.reset()` 自救。

离线看面板：直接打开 `panel/preview.html`（跑的是成品数据，内存里的假酒馆助手 API）。

> **维护提醒：不要用 PowerShell 的 `Set-Content`/`Get-Content` 改这些文档。**
> 本机是 PowerShell 5.1，它按 ANSI 读、写的时候还会加 BOM——中文会被写坏（这个工程踩过一次，
> 两份文档被写成一堆乱码，最后只能重写）。改文本一律用编辑器或写入工具；编码事故是**不可逆**的：
> 汉字后面紧跟 ASCII 标点的地方，字节会被吃掉，反解不回来。

## 生成器（M0 解析 → M6 面板分组）

`tools/gui/index.html` —— **双击就能用**的本地页面，零依赖、不联网、不改你的文件。
既能拆开看别人的预设，也能**从零搭一份自己的**，还能改**正则、脚本和面板外观**。

**不知道从哪下手 → 左栏第一项「引导：我要做什么」。** 它不是教程文章，是按"你手上有没有预设、
改到哪一步"**算出来的清单**：每一步都写清做什么、为什么、做完长什么样，旁边直接跳去对应页面。
右上角常驻 **导入预设…**、**⟳ 刷新**、**导出预设 JSON** 三个按钮（导出最常找，所以放在最显眼处）。
**⟳ 刷新** 不是浏览器那种刷新：它**不重载文档**，只把当前这一屏重新挂一遍（节点、事件、预览 iframe
全换成新的），用来解开"跑完某个功能之后页面发钝"的情况——导入的预设、M3/M5/M6 的编辑草稿、
以及**打了字还没失焦提交**的输入框内容都会原样保留。它治界面层的卡，治不了"代码把主线程占死"；
改了编辑器自己的代码要生效，仍旧得按 **Ctrl+F5**。

已实现：

- **引导**：按当前状态算出来的上手清单 + 三条常见路线（改现成的 / 从零搭 / 只配面板）。
- **M0 解析**：条目、槽位占用与冲突、变量总线（谁设/谁读/谁累加）、条目级依赖、标签族、
  外部宏与 CDN 依赖、正则与内嵌脚本清单、分组建议、诊断。
- **M1 拼装渲染**：按顺序**有状态地**展开 `{{setvar}}/{{getvar}}/{{addvar}}`，
  算出每个分段真实会变成什么、最终正文多少字、大约多少 token。
  注入位（世界书/角色卡/聊天记录）显示成占位块，不会被误读成正文。
- **M2 体检 / 待办**：把 M0 的事实与 M1 的真实展开对照一份"任何酒馆预设都该满足"的规矩，
  给「必改 / 建议 / 提示」三档清单，每条都写清**为什么、怎么改、依据是什么**。
- **M3 框架编辑 + 导出**：改顺序、开关、条目名，增删条目，把"未列入 prompt_order 的条目"加回列表或移出去；
  导出一份完整的新预设文件。
- **M4 从零搭一份**：勾模块生成**骨架**（条目名、槽位、顺序、开关 + "这条该写什么"的注释提示），
  正文一个字都不代写。
- **M5 正则编辑**：增删改排序 + 作用面勾选 + **浏览器里当场试跑**（贴一段样例，看每条匹配几处、
  一串正则按顺序跑完的最终结果），并且**左边纯文本、右边真渲染**——正则改的往往是
  `<details>` 这类结构，只看转义文本等于没看见效果。（插入前剔掉 script / on* 事件。）
- **M5 脚本编辑**：启停 / 改名 / 代码框 + **语法校验（只编译不执行）** + 与原文的 diff（删几行加几行）+ 体积提示。
- **M5 面板外观**：18 个颜色 token（白天/夜间各一套）+ 悬浮球大小与字形 + 窗口默认尺寸与上下限 +
  圆角 + 整体缩放 + 不透明度/磨砂 + **面板壁纸**，旁边就是**用面板真样式渲染的实时预览**。
- **M6 面板分组**：**按当前预设推断模块**（互斥变量→选一、addvar→可多选、注入位/初始化条目→只读、
  思维链标签族→强制互斥、写着"此处自定义"→可填输入框、剩下的按名字前缀聚组、再兜底），
  推断结果可以在界面上增删改；校验会指出"这个名字预设里没有""同一条目属于两个互斥模块"这类会静默失效的问题。
- **把面板装进任意预设**：导入一份**没有面板脚本**的预设（比如别人写的），推断分组 + 调外观，
  点「装进这份预设」就把面板脚本写进它的扩展里，跟着预设一起导出。
- 左侧 23 个视图；开关随手改随手重拼，右上角可导出解析报告（含体检清单）。

### 认得出「提示词模板」（ST-Prompt-Template / EJS）

有些预设的正文里写着 `<% … %>`——那不是给模型看的文本，而是要靠
[提示词模板（ST-Prompt-Template）](https://gitlab.com/zonde306/ST-Prompt-Template) 扩展在**发送前渲染掉**的
EJS 模板代码。这个工具会：解析时数出标签数量、在标签族里单列一族、体检里出一条提醒
（**没装或没启用那个扩展时，`<% … %>` 会原样进上下文**：白烧 token 还可能让模型跟着写代码），
渲染预览里把模板代码显示成 `‹模板: …›` 占位而不是让它消失。

> 为什么不直接执行 EJS：那是**运行任意 JavaScript**。这个页面是本地 file:// 打开的，
> 没有隔离层，替你执行一段别人的模板代码不安全也没必要——提醒你装插件才是对的。


### 可视化搭建（左栏第二项「面板搭建」）

**这一页把"看渲染"和"搭预设"合成一个面**：左边就是面板的渲染（用的是面板自己的样式表，
不是另画一个像的），右边是选中项的属性。三层结构：

| 这一层 | 是什么 | 怎么加 |
|---|---|---|
| **分节** | 面板上的大标题（"文风"、"人称与叙事"…） | 「＋新建分区」 |
| **功能区** | 一个模块（"破甲（按模型分流）"…） | 「＋在这个分区里加功能区」 |
| **功能项** | 一个**条目**（预设里真实的 prompt） | 功能区的「＋功能项」 |
| **功能选项** | 选一型功能区里的另一个条目 | 功能区的「＋功能选项」 |

- 加功能项 / 功能选项**会真的新建一个条目**（正文留空标「待填」、默认关着）并挂进那个功能区；
  想用已有的条目，用属性栏的「把已有条目挂进来」（不新建）。
- **点功能项就能就地改它的提示词正文**（右侧属性栏里直接编辑）。导入来的原文也能改——
  改过的会标「你改过」，随时能「还原成导入时的原文」；没改过的条目照旧逐条 sha1 自证"一个字没动"。
- **点分节标题**可以改分节：改名（里面的功能区跟着走）、上移下移、加功能区、删掉（里面的功能区会挪到别的分节，不会顺手丢条目）。
- **拖功能区就能换位置**（拖到别的分节里＝搬家）。
- 属性栏：改名字、改形式（选一 / 可多选 / 要你自己填 / 只读）、改说明、换分区、删除；
  选中的功能项还能一键「默认打开 / 默认关闭」「从功能区移除」（只是从面板拿掉，条目还在预设里）。
- **面板质检**（画布上方那张卡）会挑出"导进酒馆之后点了没反应 / 打开了也没用"的地方：
  挂着不存在的条目、条目重名、空功能区、**默认开着但正文是空的**、同一条目落在两个选一区……每条都带"去看"。
- 改的是**草稿**：面板自带的那份分组不会被碰；点「应用到面板脚本 / 装进这份预设」才写进去，然后导出。

**从零开始**：引导页第四条路线「我什么都没有：从一个空面板开始」会清出一块干净画布，
从「＋新建分区」一路搭到「＋功能项」。**成品预设里嵌的那个面板不带搭建功能**——搭建是解析器这一侧的事。

### 面板分组这一层解决的是什么（M6）

面板不只是外观——它得知道**管哪些条目**。我们那份面板的模块列表是给芳乃这套条目写死的
（`spec/groups.json` 25 个子集 + 分节标题），装到别人的预设上会列出一堆找不到的条目。
所以面板多了**第二段标记块** `GROUPS_OVERRIDE`（默认 `null` = 用自带那套）：

| 推断依据（全部来自解析结果里可验证的事实） | 推成面板的什么 |
|---|---|
| 同一变量被多条**非清空型**条目设置，且有人读 | 「选一（互斥）」模块 |
| 同一变量被多条 `addvar` 累加 | 「可多选」模块 |
| 占注入位槽位的条目 | 只读区（面板不碰，关掉会丢上下文） |
| 清空型初始化条目 | 只读区（面板不碰，关掉会让一批变量失去初值） |
| 思维链标签族 | 强制互斥的「思考方式（选一）」+ 族内互斥执行 |
| 正文里写着"此处自定义 / 点进去看" | 可填输入框模块 |
| 名字前缀相同（作者自己的命名习惯） | 「按名字前缀」模块（**标着是猜的**） |
| 剩下没覆盖的 | 兜底一个「其余条目」，保证没有条目够不着 |

**面板是按条目名匹配的**，所以重名条目会被排除并写明理由——否则会出现"点开一个却关掉另一个"。
推断出来的模块名都是占位（「选一 · 第 3 组」），等你改成看得懂的名字。

### 面板外观怎么落地（M5）

面板升到 **0.5.0**，外观与分组两样东西都用"标记围起来的配置块"（生成器只替换块内内容）：

> **0.6.0 起的补充**（用户点名要的三件事，规格见 `spec/SPEC.md` §5c）：
> 顶部按钮从"开合窗口"改成**整块隐藏**（连悬浮球一起，状态落盘），文案也跟着改成 `🙈 隐藏`；
> 面板里加**壁纸开关 + 纯色背景**两个控件（只在配了壁纸时出现）——"出厂开不开"是
> `CONFIG.wallpaper.enabled`、"关掉后的纯色"是配色 token `--fp-solid`，两样都能在「面板外观」里设，
> 用户点过之后以他点的为准（存本地）；
> 小方案支持**长按 chip 就地改名**。
> 另加一个**能力标记** `FANO_PANEL_CAP_CONTROLS_V06`：预设里那份面板是旧版（没这些控件）时，
> 导出前会拦住并给一键换新——免得装进酒馆"看着差不多、功能没有"。

1. **`CONFIG`（外观）**：颜色覆盖、悬浮球、窗口尺寸、圆角、缩放、不透明度、磨砂、壁纸，
   以及**长按条目改正文**这个手势（`edit.longPress`：开/关 + 毫秒）。
2. **`GROUPS_OVERRIDE`（分组）**：默认 `null`（用自带那套）；写了就按它管条目——这是把面板
   装到**别的预设**上的前提。窗口本身分四层：底色层（带不透明度与磨砂）→ 壁纸层 → 压暗层 → 内容，
   分成四层是为了让"半透明 + 壁纸 + 字还看得清"三件事互不打架。

两处实现必须一致，所以有一条测试专门**锁死**它们：`tools/test-panelconfig.mjs` 会把配置写进面板源码、
真加载面板，再拿面板自己算出的生效值和 `tools/gui/lib/panelconfig.js` 的夹取结果**逐字段比对**，
有一处漂移就报错。

**导入的预设带的是旧面板（CONFIG 里没有后来才加的键）时也要能改**：外观页读配置一律按出厂形状
**补齐**（`mergeConfig(DEFAULT_CONFIG, 读到的)`），所以老面板打开「面板外观」不会因为缺一个键整页白掉，
按一次「应用到面板脚本」还会把缺的键补进那份脚本。这一条有页面级回归用例钉着
（`check-gui-browser` 的自检里：「老面板打开『面板外观』不抛异常」）。

**预览不是"另画一个像的"**：预览用的是面板自己的那一大段 CSS，只额外加一小段"把 fixed 悬浮定位改成摆位"
的作用域覆盖——所以预览里看到的颜色/字号/圆角/壁纸，就是装上去之后的。

**诚实的三条边界**：

- **任意 JS 不可能"可视化编辑"**。脚本那一页给的是代码框 + 语法校验 + diff，改的是文本。
  任何号称能可视化改别人脚本的界面都是在骗自己——所以面板外观那条路是"配置块"，不是"生成代码"。
- **壁纸只作用在面板上**，不动酒馆整页（整页换背景是酒馆主题/插件的活，风险更大）。
  用本机图片会被内嵌成 data: 塞进预设（1MB 的图 ≈ 1.4MB），界面会提前告诉你预设会变大多少。
- `file://` 下 iframe 跨源，页面**不能**嵌一个真预览去戳它；所以实时预览是"同 token 的真样式摆位"，
  真要验货点「导出独立预览页」——那是个能双击打开的 HTML，跑的是面板本体。

### 骨架长什么样（照真实预设的实测形状生成）

- **8 个位置标记**：世界书前后、角色卡描述/性格、用户人设、场景、示例对话、聊天记录。
  它们的正文**真的是 0 字**（和真实预设一样），但必须开着——否则那些内容根本进不来。
  M1 里会显示成 `⟨世界书·前⟩ 酒馆在这儿注入`，不会被误读成你漏填。
- **main** 生成时就是**开着且待填**的：没写核心指令，导出会被拦住并点名"主提示还没写"。
- 其余条目**一律默认关**：没写内容就不该生效。开了却没写 → 导出拦住（这是"不代写"的执行点）。
- 顺序照实测的真实预设排：`main → 世界书前/人设/角色卡描述/性格/场景/世界书后 → 你的条目 → 示例对话/聊天记录 → 历史后置指令/辅助提示`。

**关键设计：预览的就是导出的。** 编辑态套到原 JSON 上现算出一份新 JSON，再解析一遍喂给所有视图——
M0/M1/M2 看的、体检的、导出的，是同一条路径出来的同一份东西，不靠"两边都改对了"的默契。

**改动只发生在结构上（对你导入的预设而言）。** 没动过的条目在导出时**复用原对象**（不是深拷贝再写回），
所以"来源一字未改"是可验证的事实：页面里显示逐条核对结果，Node 测试用 sha1 逐字节证明。
导入的预设里，来源正文**可以改**（v2.4 起放开的）——「条目」页点条目名就展开就地编辑，
「框架编辑」页也能改；改过的行会标「已改」，随时能「还原成导入时的原文」。
所以"来源提示词一字未改"这句话说的是**你没动过的那些仍然一字未改**：页面上用逐条 sha1
核对（`verifySourceIntact`），导出报告里会写明改了几条、删了几条。
新条目的正文一律从 `{{//待填：…}}` 起步：在酒馆里看得见，展开后是空的，
所以它既不会喂进模型，也不会被体检器误判成"你把占位话术发给模型了"。

### 导出前检查（拦住真正的坑）

| 检查 | 档位 |
|---|---|
| 主提示（main）没写内容却开着 | 必改（导出的预设没有核心指令） |
| 自己写的条目正文还是空的（或只有待填标记）却设成开启 | 必改（工具不替你写内容） |
| 新增条目抢了已被占用的槽位/标识 | 必改 |
| 删掉了注入位条目（世界书/角色卡就进不来了） | 必改（要清正文就清正文，别删条目） |
| 新增条目没有名字 | 必改 |
| 位置标记被关掉 | 提醒（对应内容进不了上下文；它的正文为空是**对的**） |
| 预设里那份面板是**旧版**（没有"长按条目改正文"） | 必改（有一键补救「换成新版面板」，也有活路「就带这个旧面板导出」） |
| 预设自带的面板**不是这套**（没有我们的分组块） | 提醒（人家预设里本来就有个脚本，很正常；不拦、也不提供替换） |
| 改了条目名 | 提醒（按名字匹配的面板/正则会找不到目标） |
| 把条目移出提示词列表 | 提醒（它不再进入上下文） |
| 名字重复 / 未知槽位 | 提醒 |

### 体检都查什么

| 查什么 | 档位 | 依据 |
|---|---|---|
| 注入位缺失（世界书/角色卡/聊天记录进不来） | 必改 | 生效条目里没有这些槽位标记 |
| 没有 prompt_order | 必改 | 条目的开关与顺序都不存在 |
| 槽位被两条占、且都开着 | 必改 | 酒馆一个槽位只有一个主人 |
| 主提示（main）展开后是空的 | 必改 | M1 的真实展开（只写了一句"待填"注释不算写了） |
| 两套思维链标签同时开 | 必改 | 两个互斥的标签族都有生效成员 |
| 先读后设（`getvar` 排在 `setvar` 前面） | 必改 | M1 的真实展开事件顺序 |
| "选一"的条目被同时打开 | 建议 | 同一变量有多条**非清空型**设置者，且开着多条 |
| 开关没开导致变量为空 | 建议 | 有读者开着、而所有"会给值"的写入者都关着 → **点名该开哪一条** |
| 变量拼完是空的却还被读 | 建议 | M1 的最终值 |
| 悬空变量（有人读、没人写） | 建议 | 全预设找不到 setvar/addvar |
| 不在 prompt_order 里的条目 | 建议 | 永远不会被送进模型 |
| 待填条目却开着 | 建议 | **展开后**正文里仍留着"此处自定义"之类话术 |
| 两条开着的条目展开后正文一样 | 建议 | 重复注入 |
| 依赖外部 CDN | 建议 | 正则/脚本里有 jsdelivr/fonts.googleapis 之类 |
| 带脚本但全是关的 | 建议 | 面板装不上 |
| 外部宏 / 上下文占用 | 提示 | 非酒馆原生宏；本轮 token 估算 |

实测 Izumi_0914.json：226 条 / 其中在提示词列表里 192 条 / 开启 60 条。
开启的 60 条**原文合计 10854 字**，拼装后正文只剩 **5267 字**——
差额来自 31 条"开关型"条目，它们的正文几乎全是 `setvar`，本身不产出文本。
**别拿原文合计当上下文占用**，这个差值正是 M1 存在的意义。
（token 估算会再扣掉注入位占位块——`⟨世界书·前⟩` 那些是我们画给人看的，
酒馆真正注入的是世界书/角色卡本身，所以 Izumi 那一份的净占用约 **3.5k token**。）

体检器自身的准确性也当成测试对象：**拿成品预设当反例**——它已经过了 108 项构建校验，
如果体检器在它身上报"必改"，那多半是体检器误报（测试里就是这么断言的，必改为 0）。

自检：`node tools/test-gui.mjs`（353 项，纯 Node）＋ `node tools/check-gui-browser.mjs`
（235 项页面断言 + 逐屏数 DOM，真 Chrome，桌面/手机两个视口）。

**导出前检查会盯住"面板到底进没进这个文件"**：面板是**脚本**（进 `extensions.tavern_helper.scripts`），
条目是 `prompts` ——两条不同的路。在画布上搭了功能区/改了外观却还没点「装进这份预设」时，
导出会被拦住并给出结论与一键补救；这份预设本来就没有面板（正常导入一份别人的预设只改条目）则完全不打扰。
详见 `spec/生成器设计.md` 的踩坑表（这一条是真踩出来的：导出过一份 165.8 KB 的"改"文件，里面没有面板）。

**M2 看得见 M3 的改动**（端到端锁了因果）：在成品预设上关掉 Kemini 的初始化条目 `🔗`，
体检会立刻改口——不是冤枉成"先读后设"，而是指出"这些变量没有开启的条目去设值"；打开回来，
诊断回到基线。这条测试顺带纠正了体检器的一个误报（详见 `spec/生成器设计.md`）。

**M4 的输出是"能用但空"的**：生成完做一次体检，注入位齐全、没有变量问题，唯一的必改是
"主提示还没写"。写完它就干净了——这就是这份工具的态度：结构我给，话得你说。

## 两件必须你自己做的事

1. **`💠雪融雪降` 要换成你自己的文本。** 面板 → 破甲 → Gemini → 「雪融雪降填充文本」，粘贴一段你自己的、≥7000 token 的私有小说段落再打开它。不换会秒截断；用别人也会用的段落等于没换。
2. **实测。** 本机没有酒馆、没有渠道 key，我只能保证静态校验全过（结构、槽位、引用、原文未改、面板可点）。破甲强度取决于渠道、账号、角色卡和上下文，得你在真实环境里按渠道分别试。

## 已知限制

- **切到非 Gemini 分支时，主提示与预填充位里仍是 Kemini 的文本**（`💠CLEAR` / `💠continue`）。因为它们占的是 `main` / `jailbreak` 这两个唯一槽位，而槽位按规格归 Kemini。要彻底做到"每个分支自带自己的主提示"，需要面板在切换时改写 identifier 归属——未实现，风险高于收益。
- **思维链语言（`⭐️思维链语言-*`）只对 Izumi 系的思考方式有意义**。它是 Izumi 的 `{{getvar::lan}}`，而 ICOT/COT 不读这个变量；默认走 ICOT 时它实际上不起作用。
- 折叠链只处理 `<think>` / `<thinking>` 与 `konatan_planning~` 两种标签。梦鲸那套骨架没搬它的思维链条目，所以它的 `</think>` 走的是第 1–3 条（单块 → Izumi 形态）。
- Izumi 原有 30 条美化/隐藏正则**没有**搬入——它们绑死 Izumi 自己的标签与条目结构，未经实测不敢直接塞进去。需要的话从 `Izumi_0914.json` 里挑。
- 面板目前只切**条目**，没做正则/脚本的运行时门控。
- 源预设里的 `{{压缩相邻消息::…}}` 宏（酒馆助手脚本提供）没搬；梦鲸那套骨架只用它的破甲词，不含脚本管线。
